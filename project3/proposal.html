Web Blackjack - Proposal & Documentation

High Concept

A classic, browser-based interactive Blackjack game where the player challenges the dealer. Players must strategically manage their bankroll and decide when to hit, stand, or split to build a hand closer to 21 than the dealer without busting.

Genre

Tabletop / Casino Card Game

Platform

Desktop Web (Optimized for modern browser environments).

Story

The experience is purely abstract and mechanics-driven, replicating the professional, high-stakes atmosphere of a classic casino table.

Aesthetics

The game features a clean casino aesthetic with a green felt table. It uses readable custom playing cards and clearly labeled UI widgets. To enhance immersion, it includes a looping Jazz background track and tactile sound effects for dealing, betting, and winning.

Gameplay

Players start with a $500 bankroll. Before each round, players use a dedicated betting menu to place $10 increments or go "All In." The game follows standard professional rules:

  • Actions: Hit, Stand, or Split (if cards are of identical value).
  • Dealer Rules: Dealer must hit on a soft 17.
  • Payouts: Standard wins pay 1:1, and a natural Blackjack pays 3:2.

Other Technical Details

  • Fairness & Probability: Uses a randomized 52-card deck .
  • Dynamic Difficulty Adjustment (DDA): Implemented a "Player Retention Algorithm" that subtly adjusts the card draw probability if a player faces a long losing streak to manage player engagement.
  • Audio Engine: Uses an event-based sound system to trigger specific MP3 files for different actions (e.g., betting, dealing, winning) without overlapping issues.

VI. Documentation

Development Process:

The project began with the creation of the core logic classes (Card and Deck). Once the fundamental Blackjack rules were functional, I focused on building a robust state machine to handle the betting phase, player actions, and dealer logic. A major technical hurdle was implementing the Split functionality, which required refactoring the player's hand into an array of arrays to allow independent action and scoring for multiple hands. Finally, I integrated an audio engine and a DDA system to enhance the professional feel and player retention.

Requirements Met:

  • ES6 Classes: Utilized Card and Deck classes to encapsulate data and behaviors.
  • D.R.Y. & Separation: Code is separated into classes.js, main.js, and styles.css. Functional blocks are modularized (e.g., calculateScore, updateUI).
  • DOM Traversal: Exclusively used querySelector for all UI bindings.
  • No Canvas 2D: All card rendering and layout are handled through dynamic DOM manipulation and CSS Flexbox.
  • Media: Integrated 7+ unique sound effects and a background music track. All images (backgrounds/mockups) are optimized for web delivery.
